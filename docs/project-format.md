# Project format and source identity

The `.roughscore` file remains UTF-8 JSON with document `version: 1`. Existing v1 documents are readable without a migration wizard. Optional additive `assets`, `tuningDefinition`, and per-analysis `provenance` fields preserve all existing title, duration, audioPath, tuning labels, sparse events, and analyses. Missing optional fields mean unknown/unproven data, not inferred values. Original event UUIDs, original-song seconds, lane, string, nil fret/length, tentative status, and memo are preserved exactly.

The canonical extension records are versioned independently at **1**. A reader rejects unsupported document, asset, identity, provenance, numeric-tuning, and preparation versions before activation or writing. Older clients that ignore extensions can discard them on resave; use a current client for projects containing extensions.

- `AudioAsset`: stable UUID, role `original` or `importedGuitarStem`, typed reference, optional identity, and `originalTimeOffset`. Original offsets are zero. For all consumers, `original seconds = asset seconds + offset`; an asset padded by 250ms has offset -0.25. Asset selection is independent of Stereo/L/R.
- `AudioReference`: `external` with an absolute path, or `contained` with a relative path such as `Media/<asset UUID>.caf`. Contained references reject absolute paths, empty/dot/parent components, backslashes, and NUL. Package readers must also reject symlink escape before resolving media.
- `AudioContentIdentity`: SHA-256 of the exact encoded source bytes, channel count, sample rate, frame count, identity version, and preparation version. A byte-identical relocation preserves identity; transcoding conservatively produces new identity. Preparation hashes bounded chunks before and after decode and refuses a changed source. Successful player initialization verifies the current source before activation, rejecting a mixed old-channel/new-Stereo snapshot. Player-initialization failure rehashes current readable bytes before selecting the offline fallback, with cancellation propagation and final document/load fences.
- `AnalysisProvenance`: asset UUID, full content identity, Stereo/L/R channel, analyzer version, settings, and provenance version. Legacy summaries without provenance are invalidated on preparation, relink, and offline opening. Readable corrupt replacements also invalidate summaries and clear contradicted content identity. Proven historical summaries may remain available when their media is missing or unreadable and its identity has not been disproven. Matching summaries survive a byte-identical move only while every endpoint fits the actual duration. Changed content invalidates analysis; separately imported stems are independent user assets, not derived separation results.
- `TuningDefinition`: six explicit open MIDI pitches in string order 1→6, shared across L/R, plus capo and version. Frets remain capo-relative. Legacy standard labels resolve to standard MIDI; other label-only tuning remains numerically unresolved. Numeric tuning never changes existing manual fret/string/time values. Preset editing and reverse fingering UI are implemented in #9.

The current source identity implementation populates the original asset and retains `audioPath` as its external-path compatibility alias. Original external reference and audioPath must agree. Stem consumers use the same asset record and explicit offset; portable export uses a `.roughscorepkg` directory with `project.json` and `Media/` contained references. Save As/Copy remains tracked by #14; numeric tuning and explicit fingering are implemented in #9, and same-project stem audition is documented below for #12.

A decoded valid document opens offline when audio is missing, corrupt, inaccessible, unsupported, incompatible with manual note bounds, or cannot initialize playback. Its original duration and exact manual data remain available with a repair action. Explicit relink instead validates the entire candidate against the new duration and fails atomically if any manual note falls outside it. Offline opening is not evidence of successful audio preparation.

## Same-project imported stem audition (#12)

The external original and one imported guitar stem retain independent asset IDs and encoded-byte identities. `audioPath` remains the original's compatibility alias. Opening a stem in the sidebar attaches or repairs that asset in the current document; it never imports a new project. Attach, detach and offset changes preserve the original duration, manual event UUIDs, exact times, nil pitch/rhythm, lanes, frets, tentative flags, memos and numeric tuning. Asset/channel audition is transient and does not dirty or remap notes. Stem summaries use `<asset UUID>:<stereo|left|right>` keys; original summaries retain the existing channel keys. Full provenance includes the explicit mapping offset in analyzer settings.

`AssetTimeMapping` is the canonical conversion from original seconds to asset frames using the frozen source sample rate and `originalTimeOffset`. The user supplies the offset: original seconds = file seconds + offset. A file padded by 250 ms therefore uses **-0.250 s**; a crop beginning 250 ms into the original uses **+0.250 s**. No alignment is inferred. The sidebar shows raw duration, offset, clipped valid original window and mono/stereo handling. V1 files without assets gain an original identity only after actual preparation; no stem or delay is fabricated on migration.

Preparation streams 4096-frame chunks into operation-owned Stereo/L/R audition CAFs on the original timeline. Both stereo channels are retained; mono is explicitly duplicated into L/R and the derived stereo audition file. Seek before the valid window or after a shorter stem returns silence while the native input-frame clock continues through the original duration; an entirely nonoverlapping stem is visibly an empty window. The sample-grid rounding error is less than one source sample. Neither playback rate nor a second offset enters waveform, analysis, selected-note pitch detection or region pitch proposals: those consumers read the same already-aligned files. Score and timeline therefore display the selected asset in original seconds at every playback rate. Analysis and experimental clean-mono proposals remain advisory; no TAB is automatically created or overwritten.

A new muted group is prepared before attachment commits. Original-clock handovers sample the old live clock after preparation, schedule the destination group on its native device clock, and expose it only after successful playback. Each asset group uses the existing shared AVAudioEngine mixer and one time-pitch unit for Stereo/L/R. Cancelled/late operations and preparation, playback or final source-hash failures retain the usable original, old project, dirty baseline and note history. Missing, corrupt or hash-mismatched stored stems fall back to original/TAB with repair; only contradicted stem provenance is invalidated. Byte-identical relocation preserves proven summaries; changed content or offset invalidates that asset's summaries. Offline notes remain editable even without the original.

Offset Apply is atomic and undoable, with one retired derived group retained for a single offset undo/redo transaction; ordinary note and tuning undo history remains independent. A later attach/repair or detach clears that offset transaction. Detach and shutdown stop owned native graphs before deleting only operation-created derived directories; user media and original files are never deleted. This bounds cache generations, not total disk usage: derived PCM disk quota, long-file resource profiling and cache optimization remain #13. No physical GUI, VoiceOver, real guitar isolation/model quality, signing or release quality claim follows from generated fixtures and disposable hidden native hosts.
